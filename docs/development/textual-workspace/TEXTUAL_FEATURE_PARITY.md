# Textual feature-parity audit

**4 November 2026 · current reactive application · proposed Textual access only**

Companion to [the architecture and implementation plan](TEXTUAL_WORKSPACE_INVESTIGATION.md). **I/P** means an existing implementation with a planned Textual presentation; **partial/P** identifies a narrower existing capability or explicit gap; **planned** means no equivalent current reactive feature was found. Existing feature flags, service availability and command guards still apply. “Implemented” is source evidence, not a claim that this investigation ran the feature or proved it bug-free.

The [action ledger](TEXTUAL_ACTION_INVENTORY.csv) enumerates individual source declarations and controls, including dynamic family expressions; the [shortcut ledger](TEXTUAL_SHORTCUT_INVENTORY.csv) retains platform/scope evidence. The table below assigns their families a concrete Textual destination. The complete registered Block list follows it. Every runtime-generated family must be reconciled before removing its existing access surface; extraction counts are not counts of unique user features.

**Execution note:** use this existing inventory as a reference; do not regenerate it or independently requalify every registered type. The [current four-increment plan](TEXTUAL_IMPLEMENTATION_PLAN.md) uses dedicated Textual views, representative family tests and existing regression coverage. “Same view” below refers to reusable native editor/Block rendering, not a requirement to reuse graphical application chrome.

## Reference-package reconciliation

The [supplementary asset review](TEXTUAL_ASSET_REVIEW.md) compares the supplied concept with both existing Flint screenshots. The following are explicit acceptance details in addition to the source ledger:

- Preserve dirty Document markers and all toolbar-only commands through menus, including Gloss, Initialis, style choices, Undo/Redo and the More toolsets.
- Local References retains **References / Graph / Argument**, search, type filter, counts, Navigate/Edit/Delete, incoming/outgoing sections, relationships needing attention and Add Relationship. The simplified concept image does not remove them.
- Margin cards retain **Passage / More** and source navigation when moved to the left or a full-screen fallback.
- Graph retains **Scope, Direction, Relationships, Node limit, Include unanchored, Actual size (scroll)**, counts/status and node navigation. Use a wider split/full-screen view when the reference-list width is insufficient.
- The concept's extra function-key/chord labels, Claim search row and `Enter Open` label do not establish implemented operations or approved new shortcuts. Use effective bindings and action-specific labels; LER Entity linking must retain its existing semantics.
- Supplied palette tokens and the **110-column margin / 155-column References** example thresholds inform the planned presentation, while all commands remain accessible below those thresholds.
