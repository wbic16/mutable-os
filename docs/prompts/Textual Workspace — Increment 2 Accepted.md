# Textual Workspace — Increment 2 Accepted

Increment 2 is accepted. Proceed to Increment 3.

The dedicated Textual Flint presentation, retained editor integration, bounded transaction behaviour, geometry qualification and Desktop restoration satisfy the intended scope.

The two pre-existing graphical toolbar failures are accepted as documented and should not be investigated further as part of this work.

## Instructions for Increment 3

1. **Preserve presentation isolation.** Scry/LER, Gloss, References and Cardex should receive dedicated Textual views where their existing graphical interfaces are unsuitable. Do not alter their graphical presentations merely to accommodate Textual.

2. **Reuse existing application logic.** Retain controllers, commands, state, persistence and services. Do not introduce parallel implementations of instrument functionality.

3. **Avoid speculative infrastructure.** Do not build a universal TUI framework, alternative window manager or generalized layout system unless a concrete Increment 3 requirement demonstrates the need.

4. **Use the existing Textual geometry and presentation infrastructure.** Introduce only the minimal additional primitives needed for these instruments.

5. **Respect Increment 4 boundaries.** Do not expand Increment 3 into comprehensive media layout, marginalia quantization or complex Block grid alignment. Where appropriate, use a functional interim presentation.

6. **Keep testing proportionate.** Qualify instrument opening, essential commands, navigation, editing where applicable, state preservation and return to Desktop. Reuse existing test coverage. Do not repeat the complete Increment 2 qualification matrix.

7. **Maintain the Shared-Code Impact Register.** Document any shared changes, their necessity and their effect on graphical mode. Do not create a new investigation or inventory when existing documentation is sufficient.

Proceed with the smallest practical implementation increments. Report concrete blockers or architectural conflicts rather than automatically expanding the scope or test programme.

The objective is to deliver usable, coherent Textual instrument presentations efficiently, not to reproduce every detail of their graphical counterparts or perfect a general-purpose TUI architecture.
